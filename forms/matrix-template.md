# Permission Matrix — Output Template

> Output shape for Skill 06 (Matrix Sync). The single cross-domain view of all approved subject permissions across the Entitlements platform. Produced by the Matrix Sync specialist; consumed by PMs, TLs, and stakeholders.

---

## File location

`schema/permission-matrix.md`

---

## Header block

Every generated matrix opens with this frontmatter:

```yaml
---
last_synced: YYYY-MM-DD
approved_ac_count: <total count of status:approved ACs across all domains>
source_runs:
  - runs/YYYY-MM-<name>
  - runs/YYYY-MM-<name>
open_issues: <count of ? and ⚠️ cells>
---
```

Followed by a one-line summary:

```
X approved ACs across Y domains. Last synced: YYYY-MM-DD.
```

---

## Subject type columns (standard set)

| Column header | Relation | Description |
|---|---|---|
| **Owner** | `account#owner` | Sole or primary account holder — full legal ownership |
| **Joint Holder** | `account#joint_holder` | Co-owner on a joint account — either-to-sign model default |
| **View Delegate** | `account#view_delegate` | Third-party granted read access by an account holder |
| **PoA Attorney** | `account#poa_attorney` | Holder of a registered Power of Attorney over the account |
| **Ops Internal** | `account#ops` | Internal operations staff — access conditional on customer consent or escalation |

New subject types (e.g. `appointee`, `trustee`, `guardian`) are added as new columns when the first approved AC introduces them. Document the addition below this table in the generated file.

## Cell value conventions

| Symbol | Meaning | Source |
|---|---|---|
| `✓` | Allow — an approved AC asserts `expected: allow` for this subject×action pair | AC ID in HTML comment after the cell |
| `✗` | Deny — an approved AC asserts `expected: deny` | AC ID in HTML comment |
| `~` | Conditional — `expected: conditional`; caveat condition stated in Notes column | AC ID in HTML comment |
| `—` | Not defined — no approved AC exists for this pair; do not infer | No citation |
| `?` | Conflict — two or more approved ACs contradict each other for this pair | Conflicting AC IDs in Notes column; logged in Open Issues |
| `⚠️` suffix | Schema mismatch — the permission named in the AC does not appear in the domain's `schema-fragment.zed` | Logged in Open Issues |

HTML comment format: `✓<!-- AC-A-001 -->`. For `~` cells: `~<!-- AC-A-008 -->`.

## Matrix structure per domain

One section per domain. Domain order is fixed:

1. ACCOUNTS
2. PAYMENTS
3. CARDS
4. COMMUNICATIONS
5. CUSTOMER MANAGEMENT

Within each domain, rows are grouped by use case (matching the section headings in `ac-corpus.md`), then ordered by appearance in the corpus. The use case group heading appears as a sub-header row (italicised, no cell values).

### Example section

```markdown
## ACCOUNTS

| Action | Owner | Joint Holder | View Delegate | PoA Attorney | Ops Internal | Notes |
|---|---|---|---|---|---|---|
| *UC-A-001 — Joint Current Account* | | | | | | |
| can_view_balance | ✓<!-- AC-A-001 --> | ✓<!-- AC-A-002 --> | ✓<!-- AC-A-003 --> | ✓<!-- AC-A-004 --> | ~<!-- AC-A-005 --> | Ops: on customer consent |
| can_close_account | ✓<!-- AC-A-010 --> | ~<!-- AC-A-011 --> | ✗<!-- AC-A-012 --> | ✗<!-- AC-A-013 --> | ✗<!-- AC-A-014 --> | Joint: both holders must consent |
| can_grant_delegate | ✓<!-- AC-A-020 --> | ✓<!-- AC-A-021 --> | ✗<!-- AC-A-022 --> | ✗<!-- AC-A-023 --> | ✗<!-- AC-A-024 --> | First party grants in-app |
| can_revoke_delegate | ✓<!-- AC-A-025 --> | ✓<!-- AC-A-026 --> | ✗<!-- AC-A-027 --> | ✗<!-- AC-A-028 --> | ~<!-- AC-A-029 --> | Ops: on first party request |
```

## Open issues section

Every generated matrix ends with this section. Present even when empty.

```markdown
## Open Issues

_Generated by matrix-sync on YYYY-MM-DD. Requires PM resolution before matrix is clean._

### Conflicts (? cells)

| Cell | AC IDs | Description |
|---|---|---|
| accounts / can_close_account / joint_holder | AC-A-011, AC-A-099 | AC-A-011 says conditional; AC-A-099 says deny. Corpus inconsistency. |

### Schema mismatches (⚠️ cells)

| Cell | AC ID | Permission not found in fragment |
|---|---|---|
| accounts / can_initiate_chaps / owner | AC-A-031 | `can_initiate_chaps` not in `domains/accounts/schema-fragment.zed` |

### Notable coverage gaps (— cells worth discussing)

| Subject×Action | Why it matters |
|---|---|
| poa_attorney × can_add_payee | PoA is in corpus for view and transact; add-payee is unresolved per open issue in run card |

_If there are no open issues, write: "No open issues."_
```

## Discipline

- The matrix is a **view, not a source.** If the matrix and the corpus disagree, the corpus wins. Fix the corpus, re-run Matrix Sync.
- **Never hand-edit `schema/permission-matrix.md`.** It is always regenerated from corpus state. Manual edits will be overwritten on the next sync.
- **One row per action, not one row per AC.** Multiple ACs for the same action (e.g. positive + negative) fold into one row with different column values.
- **The `—` cell is not a problem to be fixed.** It is information: this pair has not been decided yet. Do not guess.
